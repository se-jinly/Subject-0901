# Claude Code 작업 습관 (사람용 메모)

## 작업 하나의 흐름
1. 새 대화로 시작 (`/clear`) → Claude가 progress.md를 읽고 이어감
2. 큰 작업이면 계획 모드로 계획 먼저 → 확인 후 진행 (모델은 `opusplan` 추천)
3. 진행 중 코드가 바뀌면 `/check`
4. 직접 플레이해서 확인
5. 기능이 끝나면 `/done` → 커밋 → 다시 1번

## 토큰 아끼기
- 기능 하나 끝나면 `/clear`. 대화를 길게 끌지 않기
- **10분 넘게 쉬었다 오면** 같은 대화를 이어가지 말고 `/clear` 후 새로 시작
  (Claude가 잠깐 기억해둔 내용(캐시)이 사라져서, 긴 대화를 이어가면 처음부터 다시 읽는 비용이 듦)
- 곁가지 질문은 `/btw`
- 요청은 "어디 / 증상 / 목표 / 건드리지 말 것"으로 구체적으로
- 참고할 파일을 짚어주기: "@MeleeEnemy.cs 구조 참고해서 ~"
- 같은 버그에서 2번 실패하면 멈추고 `/clear` → "지금까지 이런 방법은 안 됐다"를 짧게 정리해서 새로 시작
- 하루 한 번 `/usage`, 대화가 무거우면 `/context`

## 모델 고르기
- 기본: `/model opusplan` (계획은 Opus, 실행은 Sonnet 자동)
- 쉬운 작업(주석, 이름 바꾸기, 간단한 질문): Haiku 또는 effort 낮추기
- 원인 모를 버그, 구조 변경: Opus + effort 높이기, 끝나면 다시 내리기
- Fable은 Pro에서 추가 요금이 나가니 쓰지 않기
- 모델은 대화 중간 말고 `/clear` 직후에 바꾸기

## 되돌리기
- 방금 Claude가 한 걸 취소: `Esc` 두 번 또는 `/rewind`
- 큰 작업 전엔 커밋 (세이브 포인트)
- 큰 실험은 브랜치에서

## 꼭 지킬 것
- 플레이 모드 중엔 씬 작업 시키지 않기 (플레이 멈추면 사라짐)
- 커밋 전에 유니티에서 `Ctrl+S`로 씬 저장
- git push, 삭제를 물어보면 무슨 작업인지 읽고 허락하기
- 비밀번호, API 키는 대화에 넣지 않기
- 하루 끝: 커밋 + 푸시
